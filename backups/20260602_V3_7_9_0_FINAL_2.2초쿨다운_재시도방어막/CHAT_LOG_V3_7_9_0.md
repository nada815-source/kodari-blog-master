## 🔎 1. 구글 검색 "1건"의 모델별 과금 기준 팩트체크
대표님이 **"2026 청년도약계좌 신청 자격과 은행별 금리"**라는 하나의 주제로 글을 쓰기 위해 1단계 정찰(구글 검색 연동)을 실행했을 때, AI가 내부적으로 `① 신청 자격`, `② 은행별 금리` 두 번의 검색 행위를 수행한 경우의 실제 과금 방식 비교입니다.

| 구분 | **Gemini 2.5 Flash** (현재 표준 고정) | **Gemini 3.5 Flash** (최신 표준) |
| :--- | :--- | :--- |
| **과금 기준** | **API 호출 성공 1회당 카운트** (`Per-Prompt`) | **실제 구글 검색(쿼리) 1회당 카운트** (`Per-Query`) |
| **수수료 단가** | **건당 $0.01 (한화 약 12~13원 고정)** | **건당 $0.014 (약 18~19원)** (무료 한도 초과 시) |
| **작동 예시** | 내부에서 검색어를 2개든 10개든 쪼개 돌려도, 1단계 요약본을 받아내는 데 성공한 **API 요청 1회에 대해서만 딱 12~13원** 청구. | 내부적으로 검색창 조회를 2번 수행했다면 **총 2건으로 카운트**. |
| **무료 혜택** | 없음 (첫 호출부터 고정 과금) | **매월 5,000건의 검색 쿼리 무료 제공** 🎁 |
| **본문 완성 비용** | **매우 저렴 (약 20~30원)** <br> *(토큰 단가가 저렴하여 3대 플랫폼 본문 완성 시 부담이 거의 없음)* | **다소 높음 (약 160원)** <br> *(기본 토큰 단가가 비싸 원고 전체 완성 시 요금이 많이 찍힘)* |

## 📊 2. 구글 AI Studio 지출 대시보드의 누적 정산 법칙 해명
대표님이 목격하셨던 비용 차이(어제 밤 86원 ➡️ 오늘 오전 297원 ➡️ 현재 1,038원)의 원인은 **구글 클라우드 결제 보고서의 [실시간 실소비량 누적 반영] 메커니즘**에 기인합니다.

* **구글의 요금 반영 딜레이**: 구글 클라우드는 매 요청마다 실시간으로 1원 단위 청구를 띄우지 않고, 수 시간의 사용량을 모아 배치 정산합니다.
* **1038원과 597원의 상관관계 (수학적 검증)**:
  * **어제 (6월 1일) 최종 마감 요금**: **597원** (하단 일별 그래프 파란 막대 기둥으로 고정)
  * **아침 확인 시점 (누적 894원)**: 어제 누적(597원) + 오늘 오전까지 발생한 실시간 사용량(**297원**) = **894원**
  * **현재 확인 시점 (누적 1,038원)**: 어제 누적(597원) + 오늘 오후 현재까지 발생한 실시간 사용량 총합(**441원**) = **1,038원**
* **결론**: 단건 비용 폭증이나 요금 폭탄이 아니라, 사용한 총누적 요금이 실시간 합산되는 정상 동작 흐름임을 검증했습니다.

## 🛠️ 3. V3.7.9.0 엔진 보수 & 배포 세부 내역

### 1) 2.5-Flash 모델 단일 표준 고정
* 1단계 요약 생성(`fetchSummaryDraft`) 및 2단계 플랫폼별 상세 집필(`writePlatformContent`) 주소의 모델 호출값을 모두 비용 효율성이 가장 뛰어난 `gemini-2.5-flash` 모델로 고정하여 혼선을 막았습니다.

### 2) 백그라운드 자동 재시도 헬퍼 함수 (`fetchWithRetry`) 탑재
* 구글의 트래픽 과부하 에러 발생 시 즉각 튕기지 않고, **최대 2회까지 2.5초 간격으로 백그라운드에서 재요청을 시도**하도록 안전망을 장착했습니다.

### 3) 2.2초 순차식 릴레이 쿨다운 장제
* 1단계 완료 후 2단계 진입 전: **1.0초** 강제 대기.
* 플랫폼 전환(네이버 ➡️ 티스토리 ➡️ 워드프레스) 시: 기존 1.2초에서 **2.2초(2200ms)**로 강제 쿨다운을 확장하여 구글 서버의 Rate Limit 제한을 완벽히 우회했습니다.

### 4) 업데이트 이력(코다리의 항해일지) UI 문구 동기화
* 실제 엔진 동작에 맞춰 항해일지 모달의 안내 텍스트를 병렬 및 Pro 모델 표기에서 **[2.2초 쿨다운 릴레이 및 2.5-Flash 안전 엔진 탑재]**로 투명하게 개정했습니다.

### 5) 최종 릴리즈 및 원격 동기화 완료
* **Vercel 실서버 배포**: `https://kodari-v3790.vercel.app`에 즉각 컴파일 빌드하여 최종본 가동 완료.
* **깃허브(GitHub) 백업**: `kodari-V3.7.9.0` 브랜치에 최종 코드 변경분 Push 완료.

## 📱 4. 코다리 1초 웹 변환기 모바일 듀얼 복사 패치 내역

### 1) iOS Safari 및 네이버 블로그 모바일 앱 HTML 차단 규명
* **현상**: 모바일 사파리/크롬 브라우저에서 HTML 서식(노란 형광펜, 표 테두리)을 강제로 복사하여 붙여넣어도 네이버 앱 에디터에는 서식이 전부 날아가고 `==`, `|` 등의 마크다운 기호가 그대로 노출되는 오류 발생.
* **원인**: iOS 네이버 블로그 앱의 내부 클립보드 파서가 보안 및 스크립트 차단을 위해 외부 `text/html` 스트림을 아예 차단하고 오직 일반 텍스트(`text/plain`)만 걸러 받도록 설계되어 있었던 것으로 확인.

### 2) 모바일 최적화 Plain Text 변환 엔진 탑재
* **해결책**: 모바일 전용 변환 모드를 탑재. `==형광펜==`, `++파란글씨++` 등의 특수강조 기호를 싹 지우고, 깨지는 마크다운 표(`|`)를 모바일 가로폭에 가장 적합한 **글머리 이모지 텍스트 리스트**로 실시간 자동 치환하여 순수 Plain Text로 복사해 주는 지능형 파서 구현.
* **사용성**: 모바일 네이버 블로그 앱에 붙여넣으면 기호나 표 깨짐이 전혀 없는 깔끔한 완제품 텍스트 원고가 들어가며, 사용자는 강조하고픈 단어 몇 개만 네이버 앱 자체 색상 도구로 칠해주면 10초 만에 발행 가능.

### 3) 💻 PC & 📱 모바일 듀얼 복사 버튼 분리
* **💻 PC 에디터용 복사 (색상+표 자동변환)**: PC 크롬/웨일 사용자를 위해 노란 형광펜과 테두리가 살아있는 진짜 HTML 표 객체로 복사.
* **📱 모바일 에디터용 복사 (기호청소+표텍스트화)**: 모바일 앱 사용자를 위해 기호를 청소하고 표를 텍스트화하여 복사.

### 4) 모바일 뷰포트 UI 가독성 정밀 패치
* 하단의 듀얼 복사 시스템 안내 상자(`info-box`)가 화면이 좁은 모바일 단말에서 세로로 길게 찌그러지며 글자가 단어 단위로 쪼개지던 현상을 발견.
* `display: flex` 레이아웃을 `display: block`으로 변경하고, 각 강조 뱃지(`badge-demo`)에 `white-space: nowrap`을 강제 주입하여 모바일 뷰에서도 세로 찌그러짐 없는 정갈한 안내 텍스트로 복구 완료.
